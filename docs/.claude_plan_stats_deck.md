**Dernière mise à jour :** 2026-09-24

## 🎯 Objectif

Une commande qui transforme `games.csv` en un rapport lisible par deck :

```
  📊 games.csv            ⚙️ logiciel                              📈 rapports
┌──────────────────┐    ┌────────────────────────────────────┐    ┌─────────────────────────┐
│ 1 ligne par game │    │ python -m dcprepa stats <tournoi>  │    │ stats/terra-midrange.md │
│ deck, oppo,      │ ─> │                                    │ ─> │ winrate, OTP/OTD,       │
│ position, W/L…   │    │ lire, calculer, écrire             │    │ sources, matchups…      │
└──────────────────┘    └────────────────────────────────────┘    └─────────────────────────┘
         ▲
  🃏 decks/<deck>.yaml  (nom, commandant, statut, versions)
```

**Terminé quand :** `python -m dcprepa stats relicfest-2026` écrit un `stats/<deck>.md` par deck,
conforme au modèle `_modele-deck.md`, avec des tests pour chaque calcul.

**Hors de cette branche** ⏸️ : `synthese.md`, poids méta, winrate attendu, matchups non testés
(ils ont besoin du méta MTGTop8 → branches `feat/import-meta` puis `feat/stats-synthese`).

## 🔎 Les étapes en détail

### ✅ 1. Décisions 🤔

- ✅ **BO3 ou BO1** : un match de **2 ou 3 games** est un BO3 ; un match d'**une seule game** est un BO1.
  Les BO1 comptent dans les winrates par partie, pas dans « Par match (BO3) ».
- ✅ **Tri des matchups sans méta** : par nombre de parties (décroissant) ; colonne « Poids méta » à `—`.
- ✅ **Fiche deck complète** : nouvelle fonction `load_deck_sheets()` ; `load_decks()` (import) n'est pas touchée.
- ✅ **Deck sans aucune partie** : rapport généré quand même, rempli de `—` (un rapport par fiche).
- ✅ **Qui code** : Claude code, l'utilisateur relit ; une étape à la fois, validée avant la suivante.

### ✅ 2. Lire les données 📂

```
games.csv ──read_games()──> [ {date, match_id, partie, source, deck, version, oppo, position, resultat, note/ressenti}, … ]
decks/*.yaml ──load_deck_sheets()──> { "terra-midrange": {name, commandant, statut, versions} }
```

- ✅ `read_games(path)` → `(games, errors)` : en-tête, 10 colonnes, OTP/OTD, W/L ; erreurs avec n° de ligne ; games = dicts.
- ✅ `load_deck_sheets(tournament_dir)` → `(sheets, errors)` : versions via `load_decks()`, + name / commandant / statut (`""` si vide).
- ✅ 22 tests (`test_games.py`, `test_decks.py`) ; suite : 283 OK ; essayé sur test_tournoi (19 games) et RelicFest (0).

### ✅ 3. Brique winrate 🧱

Tout le rapport repose sur une seule brique :

```
Winrate(wins=66, total=120)
   │
   ├── 10 ou plus     →  "55 % (66/120)", "12.2 % (11/90)"
   ├── moins de 10    →  "⚠️ 33.3 % (1/3)"
   └── aucune partie       →  "—"
```

- ✅ Pas d'arrondi à l'entier : au dixième, décimale nulle omise (`55 %`, `12.2 %`) ; `format_percent()` sert aussi à l'écart (`+3.2`).
- ✅ ⚠️ sous 10 (parties, ou matchs pour le BO3) ; `—` si aucune partie ; `rate` exact pour les calculs.
- ✅ 27 tests (`test_winrate.py`) ; suite : 310 OK.
- ✅ Décision : winrate par partie (toutes les games) et winrate BO3 (matchs de 2-3 games) toujours distincts ;
  rapports-modèles et conventions `stats/README.md` mis à jour (Versions et Source avec les deux).

### ✅ 4. Calculs du deck 🧮

```
games du deck ──┬── self-play (oppo « deck@version »)  ──> section Self-play   🪞
                │
                └── le reste ──┬── général (parties + BO3, 1-1 = non gagné)     📊
                               ├── par version : nb + écart parties / BO3       🔢
                               ├── OTP / OTD (par partie seulement)             🎲
                               ├── paper / cockatrice / mtgo (parties + BO3)    🌐
                               └── par oppo (parties + BO3, OTP/OTD dès 10)     ⚔️
```

- ✅ `compute_deck_stats(games, deck, versions)` → `DeckStats` ; `Record(games, bo3)` porte les deux winrates.
- ✅ Général : toutes versions réunies.
- ✅ BO3 : regrouper par `match_id`, 2 games ou plus, gagné = 2 victoires.
- ✅ Écart d'une version, parties et BO3 à part : son winrate − moyenne simple des winrates des autres versions (`+3.2`, `—` si seule).
- ✅ Matchups : triés par parties puis nom ; OTP / OTD seulement à partir de 10 parties contre l'oppo.
- ✅ Self-play : mêmes colonnes, exclu de tout le reste.
- ✅ 15 tests (`test_stats.py`) ; suite : 325 OK ; essai sur test_tournoi vérifié à la main.

### ✅ 5. Rapport Markdown 📝

- ✅ `render_deck_report(deck, sheet, stats, generated)` → le texte de `stats/<deck>.md`.
- ✅ `_modele-deck.md` n'est pas modifié : il sert de spec, le texte produit suit sa structure (titres, tableaux, ordre).
- ✅ « Winrate attendu » et « Poids méta » à `—` (méta pas encore là) ; matchups « Triés par nombre de parties (pas encore de méta) ».
- ✅ 11 tests (`test_report.py`), dont deck vide = le modèle avec son en-tête rempli ; suite : 336 OK.

### ✅ 5b. Méta s'il existe 🌍

- ✅ `storage/meta.py::load_latest_meta()` : `meta/AAAA-MM-JJ.csv` le plus récent ; pas de méta = pas d'erreur ; méta invalide = erreur bloquante.
- ✅ Avec méta : matchups triés par poids (oppos hors méta à la fin), « Poids méta » rempli, en-tête `meta/<fichier>`, « Triés par poids dans le méta ».
- ✅ Sans méta : tri par parties, « Triés par nombre de parties (pas encore de méta) ».
- ✅ 21 tests ; suite : 357 OK.

### ✅ 6. Service ⚙️

```
generate_stats(tournament_dir)
   │
   ├── 1. lire games.csv + fiches deck + méta (une erreur → rien n'est écrit 🛡️)
   ├── 2. pour chaque deck : calculer, rendre le Markdown
   ├── 3. écrire stats/<deck>.md              (fichier .tmp puis remplacement 💾)
   │
   └── StatsReport(decks, games, errors, warnings)
```

- ✅ Même règle que l'import : tout est préparé avant la moindre écriture.
- ✅ Avertissements : deck de `games.csv` sans fiche (pas de rapport), version jouée absente de la fiche.
- ✅ 12 tests (écriture + service sur mini-dépôt et test_tournoi copié) ; suite : 369 OK.
