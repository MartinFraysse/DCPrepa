**Dernière mise à jour :** 2026-09-24

## 🎯 Objectif

Une commande qui récupère le méta Duel Commander sur MTGTop8 et l'écrit dans le tournoi, au format déjà lu par les stats :

```
  🌐 MTGTop8              ⚙️ logiciel                              🌍 méta
┌──────────────────┐    ┌────────────────────────────────────┐    ┌─────────────────────────┐
│ général 2 mois   │    │ python -m dcprepa meta <tournoi>   │    │ meta/AAAA-MM-JJ/        │
│ papier 2 mois    │ ─> │                                    │ ─> │ ├── general.csv         │
│ (2 requêtes)     │    │ récupérer, nommer, compter, écrire │    │ └── paper.csv           │
└──────────────────┘    └────────────────────────────────────┘    └─────────────────────────┘
                                         ▲
                  📖 data/oppos.yaml  (noms MTGTop8 → noms de référence)
```

Un dossier daté par import, les précédents sont gardés (historique trié par date) :

```
meta/
├── README.md
├── 2026-09-10/
│   ├── general.csv          oppo,decks,poids   (MTGTop8 « Last 2 Months »)
│   └── paper.csv            oppo,decks,poids   (MTGTop8 « Paper Last 2 Months »)
└── 2026-09-24/              ← le plus récent : lu par les stats
    ├── general.csv
    └── paper.csv
```

Ensuite, `python -m dcprepa stats <tournoi>` lit le dossier le plus récent : deux colonnes « Poids papier » et « Poids général »,
matchups triés par le poids papier (à adapter : les stats lisent aujourd'hui un seul `meta/AAAA-MM-JJ.csv`).

**Terminé quand :** `python -m dcprepa meta relicfest-2026` écrit `meta/<date du jour>/general.csv` et `paper.csv`, relus sans erreur par
les stats (deux colonnes de poids, tri par papier), avec des tests pour chaque étape (sans réseau : pages MTGTop8 enregistrées dans les tests).

**Hors de cette branche** ⏸️ : `synthese.md`, winrate attendu, matchups non testés (`feat/stats-synthese`) ;
saisie des noms dans `oppos.yaml` par le logiciel (`feat/cli`).

## 🧱 Les fichiers, couche par couche

Même architecture que l'import et les stats : chaque couche n'utilise que celles du dessous.

```
src/dcprepa/
├── __main__.py                ⬜ ajouter le module « meta »                  ▶️
├── services/
│   └── import_meta.py         ⬜ import_meta() → MetaReport                  ⚙️
├── domain/                    (règles pures, sans fichier ni réseau)
│   ├── mtgtop8.py             ✅ parse_meta_page() : HTML → total + parts ‰   🔍
│   ├── meta.py                ✅ build_meta(), propose_oppos() : top 20, noms 🧮
│   ├── stats.py               ✅ tri des matchups : papier, puis général       📊
│   └── report.py              ✅ colonnes « Poids papier » et « Poids général » 📊
└── storage/                   (seuls accès à data/ et au réseau)
    ├── mtgtop8.py             ✅ fetch_meta_page() : télécharger la page      🌐
    ├── meta.py                ✅ load_latest_meta() : dossier daté, 2 fichiers 📊
    │                          ✅ + read_meta(), write_meta() (.tmp)          💾
    └── oppos.py               ✅ load_oppos() + append_oppos() (ajouts)      📖

src/tests/                     ⬜ un fichier de tests par fichier de code    🧪
    └── fixtures/              ✅ pages MTGTop8 enregistrées (tests sans réseau)
```

## 🔎 Les étapes en détail

### ✅ 1. Décisions 🤔

**Analyse de MTGTop8 (2026-09-24)** :

```
page  https://www.mtgtop8.com/format?f=EDH&meta=<période>      (liste chargée en JavaScript : inutilisable sans navigateur)
         │
         └── fragment appelé par la page, lisible sans navigateur :
             https://www.mtgtop8.com/cEDH_decks?f=EDH&show=pop&cid=&meta=<période>&gamerid1=&gamerid2=&cEDH_cp=1

<div …>1442 decks</div>                                      ← total de la période
<a href=archetype?a=2292&meta=121…>Phelia, Exuberant Shepherd</a> … 58.3 <span…>&permil;</span>
                                                               ← un archétype = un commandant (ou « Partner WUR »), part en ‰
```

- Duel Commander = format `f=EDH` ; 1 seule requête, pas de pagination (159 archétypes sur 2 mois), somme des ‰ ≈ 1000.
- Périodes (`meta=`) : 115 Last 2 Weeks · 121 Last 2 Months · 306 MTGO 2 Months · 308 Paper 2 Months · 328 Last 7 Days ·
  130 Major Events 3 Months · 209 Last 6 Months · 343 All 2026 · … (liste lisible sans navigateur dans la page `format`).
- ⚠️ Un `meta=` inconnu ne renvoie pas d'erreur mais **toute la base** (42 519 decks) : la période doit être validée.
- Nombre de decks par archétype non affiché : estimé = ‰ × total / 1000 (ex. 58.3 ‰ × 1442 ≈ 84) ; le poids, lui, est exact (‰ / 10).
- Noms : nom complet du commandant (« Terra, Magical Adept »), entités HTML (`&#039;`) ; **partenaires regroupés par couleurs**
  (« Partner WUR », « Partner BR »), pas par duo.
- `robots.txt` absent ; aucune API officielle ; urllib + re (inclus dans Python) suffisent : pas de nouvelle dépendance.

À trancher :

- ✅ **Inspecter MTGTop8** : fait, voir ci-dessus.
- ✅ **Source** : le fragment `cEDH_decks` (répartition toute faite, en ‰), une requête par import.
- ✅ **Dépendances** : `urllib` et `re` / `html` (inclus dans Python) ; aucune nouvelle dépendance.
- ✅ **Deux métas à chaque import** (remplace l'option `--periode`, retirée) : général 2 mois (`meta=121`) et papier 2 mois (`meta=308`),
  deux requêtes ; `python -m dcprepa meta <tournoi>`, sans option.
- ✅ **Rangement** : un dossier par import, `meta/AAAA-MM-JJ/`, avec `general.csv` et `paper.csv` (format `oppo,decks,poids` inchangé).
  Les imports précédents sont **gardés** (historique pour vérifier) ; les dossiers se trient par date.
- ✅ **Stats** : dossier daté le plus récent ; colonnes « Poids papier » et « Poids général » ; matchups triés par poids papier,
  puis oppos absents du papier par poids général, puis par games ; les deux fichiers sont requis (un seul → erreur).
- ✅ **Noms inconnus** : gardés tels que MTGTop8 les écrit (« Phelia, Exuberant Shepherd ») ; **un seul** avertissement récapitulatif
  (« 152 noms absents de data/oppos.yaml »), pas une ligne par nom.
- ✅ **Partenaires** : « Partner WUBG »… restent des oppos tels quels ; l'utilisateur peut les ajouter comme variante d'un duo dans `oppos.yaml`
  (ex. `Tymna/Thrasios: - Partner WUBG`) : la fusion fait le reste.
- ✅ **Fusion** : plusieurs noms MTGTop8 ramenés au même oppo → ‰ additionnés (donc poids et decks additionnés).
- ✅ **Decks et poids** : poids = ‰ / 10, au dixième (exact) ; decks = ‰ × total / 1000, arrondi à l'entier (estimé : MTGTop8 ne l'affiche pas).
- ✅ **Dossier du jour déjà présent** : ses deux fichiers sont remplacés, et c'est signalé dans le bilan ; les autres dates ne sont jamais touchées.
- ✅ **Réseau** : hors ligne, page introuvable, HTML changé, aucun archétype → erreur claire, rien écrit (tout ou rien).
- ✅ **Qui code** : Claude code, l'utilisateur relit ; une étape à la fois, validée avant la suivante.
- ✅ **Top 20** : seuls les 20 premiers oppos de **chaque** méta sont gardés (après fusion), avec leur **poids réel** (le top 20 fait ~63 %, pas 100 %).
- ✅ **Ajout automatique dans `data/oppos.yaml`** : les oppos du top 20 (des deux métas) absents de `oppos.yaml` y sont ajoutés à la fin,
  sous un commentaire daté ; nom court (avant la virgule) en référence + nom complet en variante (« Phelia: - Phelia, Exuberant Shepherd ») ;
  sans virgule ou nom court déjà pris → nom complet seul. Le méta est ensuite écrit avec ces noms courts.
- ✅ **Ancien format** (`meta/AAAA-MM-JJ.csv` à la racine) : plus lu ; celui de test_tournoi est converti en dossier daté.

### ✅ 2. Récupérer la page 🌐

- ✅ `storage/mtgtop8.py` : `META_IDS` (`general` 121, `paper` 308), `meta_url(meta_id)`, `fetch_meta_page(meta_id, opener, timeout)` → `(html, errors)`.
- ✅ Timeout 20 s, User-Agent « DCPrepa (…) » ; erreurs sans exception : HTTP (code), injoignable, délai dépassé, page vide.
- ✅ Encodage : charset annoncé (ISO-8859-1 chez MTGTop8), sinon utf-8 ; les accents arrivent en entités HTML (`&iacute;`), traduites à l'étape 3.
- ✅ 12 tests sans réseau (`opener` remplacé) ; suite : 394 OK ; essai réel : général 1447 decks, papier 1309 decks.

### ✅ 3. Lire la page 🔍

```
HTML MTGTop8 ──parse_meta_page()──> MetaPage(total=1447, entries=[("Phelia, Exuberant Shepherd", 58.1), …])  ou  erreurs
```

- ✅ `domain/mtgtop8.py::parse_meta_page(page)` → `(MetaPage | None, errors)` : total de decks + (nom, part en ‰) par archétype.
- ✅ Une ligne = un bloc `hover_tr` ; nom = lien `archetype?a=…` (entités HTML décodées, balises et espaces en trop retirés) ; part = nombre avant `&permil;` (ou `‰`).
- ✅ Page inattendue → erreur, jamais un méta vide : total introuvable, aucun archétype, ligne sans nom ou sans part, somme des ‰ à plus de 20 ‰ de 1000.
- ✅ Fixtures réelles `src/tests/fixtures/mtgtop8_general.html` (1447 decks, 159 archétypes) et `mtgtop8_paper.html` (1309, 152) ; 14 tests ; suite : 408 OK.
- Constat : 12 archétypes « Partner … » (WUR, BR, WUB, UBR, WR, WRG, WUBG, R, BRG, UG, BG, RG).

### ✅ 4. Construire le méta 🧮

```
[("Ragavan, Nimble Pilferer", 20), ("Raga", 15), ("Asmo", 42)]
        │  noms de référence (data/oppos.yaml)
        ▼
Ragavan 35 · Asmo 42      ──>   poids = decks / total × 100, au dixième
```

- ✅ `domain/meta.py::build_meta(page, oppo_index)` → `(rows, unknown)` ; `MetaRow(oppo, decks, weight)`.
- ✅ Nom de référence via l'index de `oppos.yaml` (comparaison souple) ; inconnu gardé tel quel et listé (un nom une fois).
- ✅ Fusion : ‰ additionnés par oppo ; poids = ‰ / 10 à 2 décimales (exact : 5.81) ; decks = ‰ × total / 1000 arrondi (estimé).
- ✅ Tri : poids ↓, puis nom (sans casse), puis ordre de la page.
- ✅ Top 20 : `build_meta(…, top=META_TOP)` coupe après fusion et tri ; inconnus renvoyés = ceux du top seulement.
- ✅ `propose_oppos(names, oppo_index)` → entrées à ajouter (nom court + variante, sinon nom complet ; déjà connu ou pris → ignoré / nom complet).
- ✅ 28 tests ; suite : 441 OK. Vraies pages + `oppos.yaml` actuel : 20 oppos ajoutés (union des deux tops), plus aucun inconnu ensuite ;
  top 20 = 62.8 % (général) et 63 % (papier) ; Ragavan, Kess, Tymna/Thrasios absents du méta des 2 derniers mois.

### ✅ 5. Écrire le méta 💾

- ✅ `storage/oppos.py::append_oppos(path, entries, comment)` : ajout à la fin de `oppos.yaml` (commentaires gardés), format du fichier,

- ✅ `storage/meta.py::write_meta(path, rows)` : rows = (oppo, decks, poids) ; en-tête `oppo,decks,poids`, poids sans zéro inutile (`5.81`, `60`),
  noms à virgule entre guillemets (module csv), dossier daté créé si besoin, `.tmp` puis remplacement ; autres dates jamais touchées.
- ✅ `read_meta(path, label)` extrait de `load_latest_meta()` : lecture et contrôles d'un fichier, réutilisée à l'étape 5b.
- ✅ Test aller-retour `write_meta` → `read_meta` ; 10 tests ; suite : 451 OK.
- Les deux fichiers sont préparés en mémoire par le service avant d'écrire le premier (étape 6).

### ✅ 5b. Adapter les stats 📊

```
avant   meta/2026-10-25.csv            ──> une colonne « Poids méta », tri par poids
après   meta/2026-10-25/general.csv    ─┐
        meta/2026-10-25/paper.csv      ─┴> « Poids papier » + « Poids général », tri par papier
```

- ✅ `load_latest_meta()` → `(dossier, {"general": {…}, "paper": {…}}, errors)` : dossier daté le plus récent, les deux fichiers requis

- ✅ `compute_deck_stats(…, metas)` : `MatchupStats.weight_paper` / `weight_general` ; tri papier ↓, puis général ↓, puis games ↓, puis nom.
- ✅ `render_deck_report(…, meta_dir)` : en-tête `meta/2026-09-24/` (sans méta : `meta/—`), « Triés par poids dans le méta papier », colonnes « Poids papier » + « Poids général ».
- ✅ Service (`StatsReport.meta` = dossier) et bilan : `Méta : meta/2026-09-24/ (matchups triés par poids papier).`
- ✅ Modèle `_modele-deck.md`, `synthese.md` (en-tête), conventions des 3 `stats/README.md`, les 3 `meta/README.md` réécrits ;
  méta fictif de test_tournoi converti en `meta/2026-10-25/general.csv` + `paper.csv` ; rapports régénérés.
- ✅ Tests adaptés ; suite : 457 OK.
