**Dernière mise à jour :** 2026-09-24

## 🎯 Objectif

Préparer un tournoi sans jamais ouvrir un fichier ni taper une commande : choisir un tournoi, saisir et corriger ses games,
gérer ses decks, lancer le méta et les stats, lire la synthèse. La GUI est l'interface principale du projet.

```
  🖥️ GUI (cette branche)                 ⚙️ services (déjà là)                    📂 data/
┌───────────────────────────┐    ┌─────────────────────────────────┐    ┌────────────────────────┐
│ PySide6 : tournoi, saisie,│    │ saisie   add / edit / delete …  │    │ tournaments/<slug>/    │
│ games, decks, oppos,      │ ─> │ import · meta · stats           │ ─> │ oppos.yaml             │
│ méta, stats               │    │ lecture  (nouveaux, étape 2)    │    │ stats/*.md             │
└───────────────────────────┘    └─────────────────────────────────┘    └────────────────────────┘
        affiche seulement                toute la logique
```

**Terminé quand :** `python -m dcprepa gui` ouvre l'interface ; chaque écran de la première version appelle les services existants
(aucune règle métier dans `interfaces/gui/`) ; les services de lecture sont testés ; parcours complet essayé sur `test_tournoi`.

**Hors de cette branche** ⏸️ : application installable (exécutable, raccourci bureau) ; graphiques des stats (les rapports Markdown suffisent en v1).
Pas d'accès depuis le téléphone (PySide6 = application de bureau) : l'inbox reste la saisie mobile.

## 🧱 Les fichiers, couche par couche

Même architecture que le reste : l'interface n'appelle que les services ; aucune règle métier dans `interfaces/`.

```
src/dcprepa/
├── __main__.py                ⬜ module « gui » : lance l'interface          ▶️
├── interfaces/
│   └── gui/                   ⬜ fenêtre PySide6, écrans, navigation          🖥️
├── services/
│   └── lecture.py             ✅ list_tournaments, tournament_overview, …    📖
├── domain/                    ✅ matches.py : group_matches, MatchSummary, date_key
└── storage/                   🔁 lectures existantes réutilisées             📂
                                  (load_deck_sheets, load_oppos, read_games, load_latest_meta)

src/tests/                     ⬜ services de lecture ; interface : tests légers (pytest-qt)    🧪
```

## 🔎 Les étapes en détail

### ✅ 1. Décisions 🤔

Validé par l'utilisateur pour la V1 (2026-09-24) :

Tranché par l'utilisateur (2026-09-24) :

- ✅ **Technologie : PySide6 (Qt)**, application de bureau (Linux et Windows).
  Comparée à NiceGUI (web local, ouvrable depuis le téléphone, code plus court mais bibliothèque plus jeune) :
  choix de la stabilité et d'une vraie application de bureau, installable plus tard ; le téléphone garde l'inbox.
  Options écartées : Tkinter (aspect daté, peu testable), Flask (HTML à écrire), Textual (reste un terminal).

Validé par l'utilisateur pour la V1 (2026-09-24) :

- ✅ **Dépendance** : `PySide6` dans `src/requirements.txt` (seule nouvelle dépendance d'exécution).
- ✅ **Tests de l'interface** : `pytest-qt` dans `src/requirements-dev.txt` pour quelques tests d'écrans (remplir un formulaire,
  cliquer, lire le bilan) ; l'essentiel reste testé dans les services. Tests lancés sans écran (`QT_QPA_PLATFORM=offscreen`).
- ✅ **Écrans de la v1** (par priorité) :

| Écran | Contenu | Services appelés |
|---|---|---|
| 🏠 Accueil | choisir ou créer un tournoi | `list_tournaments`, `create_tournament` |
| 🎮 Saisie | formulaire d'une session (champs de l'inbox, listes déroulantes decks / versions / oppos) | `add_games` |
| 📋 Games | liste des BO, corriger une game ou un BO, supprimer | `edit_game`, `edit_match`, `delete_game`, `delete_match` |
| 🃏 Decks | liste avec statut, créer, nouvelle version, statut, appellations | `create_deck`, `add_version`, `set_status`, `edit_deck`, `add_deck_alias` |
| ⚔️ Oppos | liste, ajouter un oppo ou une variante | `add_oppo` |
| 📈 Stats | boutons méta / stats, lecture de la synthèse et des rapports | `import_meta`, `generate_stats` |
| 📥 Inbox | importer l'inbox du téléphone | `import_inbox` |

- ✅ **Lancement** : `python -m dcprepa gui` (nouveau module) ; ouvre la fenêtre.
- ✅ **Disposition** : une fenêtre, le tournoi choisi en haut, un onglet par écran (Saisie, Games, Decks, Oppos, Stats) ;
  bilans affichés dans une zone de messages en bas (✅ / ❌ / ⚠️).
- ✅ **Services de lecture** : un fichier `services/lecture.py`, qui renvoie des données prêtes à afficher, pour que l'interface
  ne lise jamais un fichier elle-même.
- ✅ **Qui code** : Claude code et explique chaque étape ; l'utilisateur supervise et valide avant la suivante.

### 🔄 2. Services de lecture 📖

Chaque fonction renvoie (données, erreurs), comme les lectures de `storage/` ; avec une erreur, l'interface l'affiche.

- ✅ `services/lecture.py::list_tournaments(data_dir)` → `TournamentSummary` (slug, nom, date, nombre de games ; None si `games.csv` invalide),
  triés par date de l'événement ; un tournoi abîmé reste listé (pour pouvoir le réparer).
- ✅ `tournament_overview(tournament_dir)` → `TournamentOverview` (fiche, decks avec statut et versions, méta utilisé, rapports présents).
- ✅ `list_matches(tournament_dir)` → `MatchSummary` (`domain/matches.py::group_matches` : BO regroupés, games triées, score, issue W / L / nul),
  du plus récent au plus ancien.
- ✅ `list_oppos(oppos_path)` (triés) ; `list_reports` (synthèse d'abord) ; `read_report(tournament_dir, name)` : seuls les rapports listés se lisent
  (un nom avec `../` ou inconnu est refusé).
- ✅ `storage/tournament.py::load_tournament_sheet` (fiche complète) ; `domain/matches.py::date_key` (tri par date, partagé).
- ✅ Tests : `domain/test_matches.py` (6), `storage/test_tournament.py` (+1), `services/test_lecture.py` (12, dont noms de rapport piégés) ; suite : 684 OK.
- ⬜ Relecture et commit par l'utilisateur.
