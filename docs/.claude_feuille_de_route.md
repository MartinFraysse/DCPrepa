> Les branches faites et celles qui restent pour finaliser DCPrepa, dans l'ordre conseillé.

> Chaque branche a son plan détaillé (`docs/.claude_plan_<sujet>.md`, à partir de `docs/.claude_plan_modele.md`).

## 🗺️ Vue d'ensemble

```
 ✅ feat/project-setup      structure du dépôt, règles, doc                    🏗️
        │
 ✅ feat/format-data        data/, modèle de tournoi, rapports-modèles  (#1 #2) 🗂️
        │
 ✅ feat/import-inbox       inbox.yaml ──> games.csv                    (#3)    📥
        │
 ✅ feat/stats-deck         games.csv ──> stats/<deck>.md               (#4)    📊
        │
 ✅ feat/import-meta        MTGTop8 ──> meta/AAAA-MM-JJ/ (général + papier) (#5) 🌍
        │
 ✅ feat/stats-synthese     stats/synthese.md, winrate attendu, non testés (#6) 🧭
        │
 ✅ feat/saisie            services + modules de saisie                (#7)    ✍️
        │
 🔄 feat/gui                interface graphique                                 🖥️

 En parallèle, à tout moment :
 ⬜ docs/…                  pages officielles manquantes de docs/               📚
```

Pourquoi cet ordre : la synthèse a besoin du méta (poids, top 10) ; la GUI appelle directement les services,
autant qu'ils soient tous là (et testés) avant. Pas de CLI complète : la GUI sera la seule interface
(décision 2026-09-24) ; le lancement minimal `__main__.py` reste pour dépanner.

### 🔄 `feat/gui` — interface graphique 🖥️

- Interface qui appelle directement les services (import, stats, méta, saisie) ; seule interface du projet.
- Technologie : PySide6 (Qt), application de bureau (décision utilisateur) ; le téléphone garde l'inbox.
- V1 validée : une fenêtre, tournoi choisi en haut, onglets Saisie / Games / Decks / Oppos / Stats, zone de bilans ; `python -m dcprepa gui` ; tests avec pytest-qt.
- Plan détaillé : `docs/.claude_plan_gui.md`.
